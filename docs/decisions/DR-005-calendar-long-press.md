# DR-005. 달력 칸을 길게 눌러 그날 메모를 연다

- **날짜**: 2026-08-07
- **상태**: 결정됨

## 맥락

메모를 쓰는 입구가 연필 아이콘뿐이라 **항상 오늘 날짜로** 열렸다. 어제 일을 적으려면
팝업을 연 뒤 날짜 선택기로 옮겨야 했다 — 달력에서 그 날짜를 보고 있는데도.

달력 칸의 탭은 출석 토글이 차지하고 있어(그건 이 앱의 핵심 동작이라 양보할 수 없다)
같은 칸에 두 번째 동작을 얹을 방법이 문제였다.

## 검토한 선택지

### 옵션 A: 칸마다 메모 버튼
- 장점: 명확하고 접근성도 좋다
- 단점: **42칸에 버튼이 하나씩 더 붙는다.** 달력이 빽빽해지고, 손가락으로 정확히
  누르기엔 칸이 작다

### 옵션 B: 모드 전환 (「메모 모드」 토글)
- 장점: 제스처를 안 쓴다
- 단점: 상태가 하나 늘고, 모드를 잊으면 출석이 안 찍힌다. 매일 쓰는 동작 앞에
  모드를 두는 건 나쁜 거래다

### 옵션 C: 롱프레스
- 장점: **화면에 아무것도 안 늘어난다.** 모바일에서 익숙한 관용구
- 단점: 발견되기 어렵다. 그리고 웹에서 구현이 은근히 까다롭다 —
  click 억제·스크롤 구분·컨텍스트 메뉴 세 가지를 다 처리해야 한다

## 고민 과정

이 앱은 「편의 기능보다 화면의 간결함」을 계속 택해 왔다 (출석 체크 전용 버튼을 두지 않은 것,
공유 카드에 숫자를 넣지 않은 것). A 는 그 원칙과 정면으로 부딪히고, B 는 매일 쓰는 동작을
느리게 만든다.

C 의 「구현이 까다롭다」는 실제로 확인이 필요한 항목이었다. 만들어 보니 세 가지 모두
알려진 처방이 있고, **브라우저에서 실제로 눌러 검증할 수 있었다** (`dev/smoke.py`).
특히 「롱프레스가 출석을 토글하지 않는다」는 테스트로 못 박아 두었다 — 이게 깨지면
메모를 열면서 출석까지 켜지는 최악의 오작동이 된다.

「발견되기 어렵다」는 남는 문제라, 메모가 하나도 없을 때의 안내 문구에 두 입구를 함께 적고
README 에도 넣었다. 데스크톱에서는 우클릭이 같은 일을 하고, 툴팁도 붙는다.

## 결정

**옵션 C (롱프레스)** 채택. 데스크톱 우클릭과 툴팁을 곁들인다.

채택 이유: 화면을 늘리지 않고 매일 쓰는 동작도 느리게 하지 않는 유일한 선택지이고,
구현 위험은 브라우저 테스트로 닫을 수 있었다.

## 영향

- `app.js` 에 `longPressStart` / `longPressMove` / `longPressCancel` / `longPressMenu` /
  `consumeLongPress`. 핸들러는 격자에 위임한다 (칸은 매 렌더마다 새로 만들어진다)
- 달력 칸 CSS 에 `-webkit-touch-callout: none` + `user-select: none` (iOS 선택 콜아웃)
- **키보드에는 대응 제스처가 없다.** 연필 → 날짜 선택기가 같은 일을 하므로 기능 손실은 없다
- 재검토 조건: 실제로 오작동(메모 열면서 출석 토글) 신고가 들어오면 A 로 되돌린다
