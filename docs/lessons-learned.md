# 교훈 기록 (Lessons Learned)

비자명한 기술적 교훈만 남긴다 — "당연히 X 인 줄 알았는데 실은 Y 였다" 류.
평범한 리팩토링이나 커밋 메시지만 읽어도 아는 것은 적지 않는다.

## M7-1. 문서 단위 `updatedAt` 을 "켠 시각" 대용으로 쓰면 툼스톤이 전부 진다

- **상황**: 동기화 병합에서 항목의 생사를 「켠 시각 vs 끈 시각」으로 가린다. 끈 시각은
  툼스톤에 있는데 켠 시각은 저장하지 않고 문서의 `updatedAt` 으로 근사하고 있었다.
  기존 문서는 이걸 "남는 모호함 — 실사용에서 문제된 적 없음" 으로 적어 두었다.
- **증상**: 폰에서 취소한 출석이 PC 를 열자 되살아난다. 승급 이력을 지워도, 분류를 지워도
  똑같이 돌아온다. 재현 조건이 특별하지 않다 — **한쪽에서 지우고, 다른 쪽에서 아무거나
  하나 고친 뒤 동기화하면** 항상 그렇다.
- **원인**: `updatedAt` 은 그 문서의 **마지막** 변경 시각이다. 그러므로 8/5 에 다른 날짜를
  하나 체크하면 8/1 을 포함한 **모든** 살아있는 날짜의 주장 시각이 8/5 로 함께 밀려,
  8/2 에 찍힌 취소 툼스톤을 이긴다. "가끔 판정이 뒤집힐 수 있다"가 아니라
  **문서에 변경이 한 번이라도 더 일어나면 항상 이긴다.**
- **처방**: 항목마다 시각을 갖는다 — 출석은 `checked: {날짜: ISO}`, 승급 이력·분류는 `at`.
  메모(`notes[d].at`)가 이미 쓰던 방식이라 규칙이 하나로 합쳐졌다.
  옛 문서는 읽는 시점에 `updatedAt` 으로 **한 번 채워 확정**한다 — 채우지 않고 병합 때
  대체하면 같은 버그가 옛 날짜에 그대로 남는다.
  `app.js :: normalize` · `app.js :: pickByStamp` · `app.js :: mergeStates`
- **관련**: [DR-001](decisions/DR-001-per-item-sync-stamps.md),
  `test/merge.test.mjs` 의 "회귀:" 로 시작하는 세 케이스

### 남기는 규칙

**분산 병합에서 "언제"를 문서 단위로 재면 안 된다.** 판정 단위와 시각 단위가 같아야 한다.
이 프로젝트는 같은 함정을 출석·승급 이력·분류에서 **세 번** 밟았다 (합집합 → 툼스톤 도입,
그리고 이번의 시각 단위). 새 컬렉션을 동기화 대상에 넣을 때는 처음부터 항목별 시각을 준다.

## M7-2. 30줄짜리 테스트가 문서보다 먼저 진실을 말한다

- **상황**: M7-1 의 병합 동작을 코드만 읽고 판단하려 했다. 문서(`data-format.md` §7.2)는
  "실사용에서 문제된 적 없다"고 적혀 있었다.
- **증상**: 읽기로는 "가끔 뒤집힐 수 있는 정도"로 보였다. 실제로는 흔한 경로였다.
- **원인**: `pickByStamp` 는 인자가 넷이고 클로저 안에서 문서 시각을 참조한다. 읽어서
  "그럴 수 있겠다"까지는 가지만 **얼마나 자주 그런지**는 값을 넣어 봐야 안다.
- **처방**: 앱 코드를 그대로 복사한 30줄짜리 node 스크립트로 시나리오를 돌렸다.
  그 자리에서 `true` 가 나왔고, 그게 그대로 회귀 테스트가 됐다.
  이후 `node:vm` 하네스로 정식화 — 앱 코드에 export 를 한 줄도 넣지 않는다.
  `test/harness.mjs`
- **관련**: [DR-003](decisions/DR-003-test-strategy.md)

## M7-3. 빈 문자열로 저장한 시각이 자기 백업을 거부하게 만든다

- **상황**: M7-1 의 항목별 시각을 넣으면서, 값이 없으면 문서의 `updatedAt` 으로 채우도록 했다.
- **증상**: **첫 실행 직후** 백업을 내보내면 복원이 거부된다 —
  `tags["class"].at 이 비어 있습니다`.
- **원인**: 첫 실행에는 문서의 `updatedAt` 조차 `""` 다. 그래서 `at: ""` 가 저장되는데,
  복원 검증은 「있으면 비어 있지 않아야 한다」로 되어 있다. 값이 **없는 것**과
  **비어 있는 것**을 다르게 취급한 것이 원인이다.
- **처방**: 빈 시각은 **아예 넣지 않는다** (`withAt` 헬퍼). 없는 것과 뜻이 같기 때문이다 —
  병합에서 둘 다 "가장 오래됨"으로 취급된다. `app.js :: withAt`
- **관련**: 브라우저 스모크의 "내보낸 백업이 자기 검증을 통과한다" 가 잡았다.
  순수 함수 테스트만으로는 못 잡았다 — **첫 실행 상태**를 만들어야 드러나기 때문이다.

### 남기는 규칙

내보내기 ↔ 검증 ↔ 정규화는 **왕복 테스트**로 묶어 둔다. 셋이 같은 규칙을 각자 적고 있으면
언젠가 어긋나고, 어긋난 것은 "자기가 만든 백업을 자기가 거부한다"로 나타난다.

## M7-4. `pointer-events: none` 은 탭 순서를 막지 않는다

- **상황**: 달력의 이웃 달·미래 칸은 CSS `pointer-events: none` 으로 클릭을 막고 있었다.
- **증상**: 키보드로 달력을 지나가려면 누를 수 없는 칸 스물몇 개를 탭으로 넘겨야 한다.
  스크린리더로는 그 칸들이 그냥 "15", "16" 으로 읽힌다.
- **원인**: `pointer-events` 는 **포인터** 입력만 다룬다. 포커스와 접근성 트리는 그대로다.
- **처방**: `disabled` 를 함께 준다. 색이 흐려질 걱정은 없다 —
  작성자 스타일(`.day { color }`)이 UA 의 `:disabled` 규칙을 이긴다.
  누를 수 있는 칸에는 `aria-label`(날짜·요일·상태)과 `aria-pressed` 를 준다.
  `app.js :: renderCalendar`

## M7-5. `node --test test/` 는 디렉터리를 모듈로 해석한다

- **상황**: 테스트를 추가하고 `node --test test/` 로 돌렸다.
- **증상**: `Error: Cannot find module '.../test'`
- **원인**: 인자가 **디렉터리**면 러너가 아니라 모듈 로더가 먼저 받는다.
- **처방**: 셸 글로빙을 쓴다 — `node --test "test/*.test.mjs"`. (따옴표가 없으면 셸이 먼저
  펼쳐 결과는 같지만, 파일이 없을 때 동작이 셸마다 달라진다.)

## M9-5. 안내의 우선순위를 «호출 순서»에 기대면 리팩터링 한 번에 뒤집힌다

- **상황**: 저장 실패(`localStorage` 초과)를 토스트로 알린다. 출석 토글은 저장 뒤에
  「출석 완료」 토스트를 띄운다.
- **증상**: 저장 공간이 꽉 찬 상태에서 출석을 체크하면 **「저장 실패」가 순식간에
  「출석 완료 💪」로 덮인다.** 저장되지도 않은 것을 성공으로 알리는 셈이다.
- **원인**: 원래 코드는 `toast(성공)` → `save()` 순서라 실패 안내가 **나중에** 떠서 이겼다.
  토글을 `checkDay()` / `uncheckDay()` 로 쪼개면서 `save()` 가 앞으로 갔고, 그 순간 뒤집혔다.
  **의도가 코드에 적혀 있지 않고 줄 순서에만 있었다.**
- **처방**: `save()` · `saveNotes()` 가 성공 여부를 돌려주고, 부르는 쪽은 성공했을 때만
  완료 안내를 띄운다. 같은 결함이 메모 저장·삭제·분류 추가/삭제에도 있었다(기존부터).
  `app.js :: save` · `notes.js :: saveNotes`
- **관련**: 「저장 공간 초과」 스모크 검사가 잡았다. 이 검사가 없었으면 못 봤다.

### 남기는 규칙

**"A 가 B 를 덮으면 안 된다"는 규칙은 순서가 아니라 값으로 표현한다.** 순서는 리팩터링에
살아남지 못한다. 그리고 실패 경로는 눈으로 보기 어려우니 테스트로 못 박아 둔다.

## M9-4. 홈 화면에서만 드러나는 레이아웃 문제는 브라우저로 아무리 봐도 안 보인다

- **상황**: PWA 자산을 넣고 「홈 화면에 올려두세요」를 README 에서 강조했다. 브라우저에서는
  모든 화면이 멀쩡했다.
- **증상**: 홈 화면에서 실행하면 **맨 위 벨트가 상태바·노치에 통째로 가린다.**
  하필 이 앱에서 가장 중요한 「지금 내 등급」이 사라진다.
- **원인**: `apple-mobile-web-app-status-bar-style: black-translucent` +
  `viewport-fit=cover` 는 내용을 상태바 **아래까지** 그린다. 그런데 위쪽 안전영역 여백이
  없었다 (실측 안전영역 59px vs 벨트 상단 26px). 세 메타 태그 모두 최초 커밋부터 있었으니
  **처음부터 있던 버그**인데, 브라우저 탭에서는 안전영역이 0이라 영영 안 보였다.
- **처방**: `env(safe-area-inset-top)` 을 `.wrap` 여백 · `body::before` 배경 띠 ·
  `.page-top` sticky `top` 세 곳에 넣고, 그 값을 쓰는 JS(`notes.js :: stickOffset`)도 맞췄다.
  `env()` 는 안전영역이 없으면 0 이라 다른 환경은 그대로다.
- **관련**: 크로미움의 `Emulation.setSafeAreaInsetsOverride` 로 재현·검증했다
  (`dev/smoke.py` — 「안전영역」 절)

### 남기는 규칙

**실행 형태가 여러 가지면 테스트도 그 형태로 해야 한다.** 이 앱은 「브라우저 탭」과
「홈 화면 앱」 두 가지로 도는데, 후자에서만 참인 조건(안전영역·standalone)이 있다.
그리고 여백을 비켜 주는 것만으로는 부족했다 — **반투명 상태바 뒤에는 배경을 직접 깔아야**
스크롤한 글자가 시계 옆을 지나가지 않는다.

## M9-1. 키가 사용자 입력이면 `{}` 를 사전으로 쓰면 안 된다

- **상황**: 분류(태그) id 는 사용자가 만든 이름 그 자체다 (10자 이하). 삭제 툼스톤
  `removedTags` 는 그 id 를 키로 하는 평범한 객체였다.
- **증상**: 세 가지가 한꺼번에 나왔다. 분류 이름을 `toString` 으로 지으면 **저장 직후
  사라지고**, `__proto__` 로 지으면 **삭제가 다른 기기로 전파되지 않고**, 그런 분류가 든
  백업은 **복원이 거부**된다(`"toString" 가 tags 와 removedTags 양쪽에 있습니다`).
- **원인**: 전부 `Object.prototype` 때문이다.
  `map["toString"]` 은 함수를 돌려주므로 「툼스톤이 있다」로 읽히고,
  `map["__proto__"] = "문자열"` 은 setter 라 **조용히 무시**되며,
  `"toString" in map` 은 프로토타입 체인을 타서 늘 참이다.
- **처방**: 사전은 `Object.create(null)` 로 만들고(`app.js :: dict`), 원시 JSON 을 검사할 때는
  `in` 대신 `Object.hasOwn()` 을 쓴다. `app.js :: stampMap` · `app.js :: pickByStamp` ·
  `app.js :: validateBackup`
- **관련**: `test/edge.test.mjs` 의 `PROTO_NAMES` 루프

### 남기는 규칙

**키가 데이터면 사전은 프로토타입 없이 만든다.** 날짜처럼 형식이 고정된 키에는 사고가 안 나지만,
사전을 종류별로 다르게 만들면 어느 것이 안전한지 매번 따져야 한다 — 전부 같은 규칙으로 둔다.
JSON 으로 저장된 모양은 평범한 객체와 똑같으므로, **읽는 쪽에서 같은 함정을 다시 밟기 쉽다.**

## M9-2. 문자 길이 상한은 글자를 쪼갤 수 있다

- **상황**: 메모 500자, 분류 이름 10자 상한을 `slice()` 로 잘랐다.
- **증상**: 이모지가 섞인 긴 메모를 붙여넣으면 끝에 `�` 가 남는다.
- **원인**: 상한이 UTF-16 코드 유닛 기준인데 이모지는 두 유닛이다. 경계가 서러게이트 쌍의
  한가운데 떨어지면 반쪽만 남는다. `"a" + "🥋".repeat(300)` 이 정확히 그 경우다.
- **처방**: 자를 때 마지막이 서러게이트 상반이면 한 칸 앞에서 끊는다 (`app.js :: clip`).
  코드 포인트 단위로 세는 방법도 있지만, 그러면 `maxlength` · 화면의 `N / 500` 과 단위가
  어긋나 세 곳을 다 바꿔야 한다.

## M9-3. 테스트 셀렉터가 두 화면에 걸치면 나중에 이상하게 실패한다

- **상황**: 브라우저 테스트가 오늘 칸을 `.cal-grid .day.today` 로 잡고 있었다.
- **증상**: 앞쪽 검사는 다 통과하는데, 뒤쪽에서 갑자기
  `element is not visible` 로 30초 타임아웃. 앱을 아무리 봐도 멀쩡했다.
- **원인**: **날짜 선택기도 `.cal-grid` 를 쓴다.** 선택기를 한 번 연 뒤로는 숨겨진 선택기
  격자에도 `.day.today` 가 남아, 셀렉터가 그쪽을 먼저 잡았다. 앱 버그가 아니라 테스트 버그다.
- **처방**: 달력을 가리킬 땐 `#calGrid` 로 좁힌다. **공유하는 클래스는 테스트에서 앵커로
  쓰지 않는다** — 스타일을 재사용하려고 붙인 이름이지 신원이 아니다.

## M8-1. "데이터가 있다"에서 "그 기능을 원한다"를 추론하면 안 된다

- **상황**: 승급 추적을 옵션으로 뺄 때, 기본값을 어떻게 정할지 고민했다. 「승급 이력이 있으면
  켜진 것으로」가 자연스러워 보였다 — 이미 쓰던 사람의 화면이 안 비니까.
- **증상**: 그 규칙에서는 **「이력은 남기되 추적은 끄고 싶다」를 표현할 수 없다.**
  끄려면 이력을 지워야 하는데, 이력을 지우면 현재 벨트도 사라진다.
- **원인**: 두 가지를 한 필드로 겸했다. `history` 는 *"내 벨트가 무엇인가"* 라는 사실이고,
  추적은 *"이 체육관 기준의 예측을 보고 싶은가"* 라는 의사다. 전자가 있다고 후자가 따라오지 않는다.
- **처방**: 필드를 나눈다 (`trackPromotion`). 기본값은 추론하지 않고 그냥 꺼짐.
  마이그레이션에도 예외를 두지 않는다 — 「이력이 있으면 켬」을 마이그레이션에 넣으면
  같은 잘못된 추론이 규칙에 숨어 들어간다.
  `app.js :: normalize` · [DR-006](decisions/DR-006-optional-promotion-tracking.md)

### 남기는 규칙

**옵션의 기본값을 기존 데이터로부터 추론하고 싶어지면, 그 추론이 문장으로 참인지 먼저 써 본다.**
「X 를 기록했으니 Y 를 원할 것이다」가 어색하게 읽히면 그건 두 개의 사실이고, 필드도 둘이어야 한다.

또 하나 — **틀린 숫자를 보여주는 것이 아무 숫자도 안 보여주는 것보다 나쁘다.**
그래서 남의 체육관 기준에 기대는 화면은 기본을 끔으로 두었다.

## M7-6. vm 컨텍스트가 만든 배열은 `deepStrictEqual` 을 통과하지 못한다

- **상황**: `node:vm` 에 앱을 올리고 병합 결과를 `assert.deepStrictEqual` 로 비교했다.
- **증상**: `Values have same structure but are not reference-equal: [ '2026-08-09' ]` —
  눈으로는 똑같은데 실패한다.
- **원인**: vm 컨텍스트는 자기 realm 의 `Array`·`Object` 를 갖는다. 값은 같아도
  프로토타입이 달라 strict 비교가 떨어진다.
- **처방**: 비교 전에 JSON 왕복으로 평평하게 옮긴다 (`plain()`). 덤으로 "결과가 직렬화
  가능한가"까지 함께 확인된다. `test/harness.mjs :: plain`
